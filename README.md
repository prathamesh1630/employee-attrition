# Employee Attrition Prediction

A machine learning project that explores employee attrition in the IBM HR Analytics dataset, compares classification models, and provides a Streamlit interface for estimating attrition risk from a small set of employee attributes.

> **Project status:** The source data, notebooks, model feature manifest, and Streamlit app are included. The trained model and processed data are generated by the notebooks and are not currently checked in. Run the data preparation and model training notebooks before launching the app.

## What this project covers

- Exploratory review of the employee dataset and its target distribution.
- Feature engineering and comparison of baseline and tuned classifiers.
- Evaluation that considers precision, recall, F1, and ROC-AUC for the minority attrition class, not accuracy alone.
- A Streamlit form that uses the selected model to return an estimated attrition probability.

## Dataset

The project uses the [IBM HR Analytics Employee Attrition & Performance dataset](https://www.ibm.com/communities/analytics/watson-analytics-blog/hr-employee-attrition/), with 1,470 employee records and a binary `Attrition` target. The source file is `data/WA_Fn-UseC_-HR-Employee-Attrition.csv`. The dataset is commonly distributed for learning and demonstration; it is not a representative sample of every workforce.

## Model results

The tuned notebook uses a stratified 80/20 train/test split (294 test records) and five-fold cross-validation for hyperparameter selection. The recorded test results for the reduced feature set are:

| Model | Accuracy | Attrition precision | Attrition recall | Attrition F1 | ROC-AUC |
| --- | ---: | ---: | ---: | ---: | ---: |
| Logistic Regression | 0.731 | 0.349 | 0.787 | 0.484 | 0.790 |
| Random Forest | 0.844 | 0.524 | 0.234 | 0.324 | 0.795 |

The notebook selects Random Forest by ROC-AUC. The results show the tradeoff: at the default decision threshold, the Logistic Regression model catches more employees who left, while the Random Forest has higher precision and accuracy. These metrics describe one held-out split and should not be treated as validated performance in a real organization.

## Setup and run

Use Python 3.10 or later. From the repository root:

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate

python -m pip install -r requirements.txt
```

Run the notebooks in order using Jupyter, with the working directory set to `notebooks/` so their relative paths resolve:

1. `01_data_snapshot.ipynb`
2. `02_feature_engineering.ipynb` — creates `data/processed/cleaned.csv`.
3. `03_feature_scaling_modelprep.ipynb`
4. `04_model_training_baseline_models .ipynb`
5. `05_model_tuning and insights.ipynb` — creates `models/best_model.pkl` and updates `models/feature_manifest.json`.

Then, from the repository root, start the app:

```bash
streamlit run app/Streamlite_UI_app.py
```

The app requires the generated `models/best_model.pkl`. The checked-in feature manifest records the expected input columns and model feature set.

## Project limitations and responsible use

- The dataset is small, imbalanced, and not documented as representative of a particular employer or current workforce.
- The reported test metrics come from a single split; performance, calibration, and fairness across employee groups need further validation.
- Predictions are estimates from historical correlations. They do not explain an individual's circumstances or establish why an employee may leave.
- This is a portfolio and educational project, not a tool for employment decisions. Do not use its predictions to make decisions about hiring, promotion, compensation, or termination.
